# Exercised runtime contract

Python 3.12; openai-agents **0.23.1**, OpenAI **3.31.0**, httpx2 **2.13.1**, Pydantic **2.14.1**. uv.lock records exact dependencies. Normal native execution uses an explicit OpenAIResponsesModel with an owned AsyncOpenAI client and supplied owned HTTPX2 client; no default/global SDK client or model provider is used. Caller-supplied transports are consumed when the HTTP client is constructed. Startup failure closes already-created resources. JSON Responses is qualified; wire SSE/WebSocket, provider tools, remote conversation IDs and external calendar/email connectors are not.

The baseline SDK already stopped incomplete/failed Responses, but absent status still dispatched a confirmation tool. Public HTTP response hooks now require completed response/item metadata before SDK parsing, reject unsupported/mixed/unknown/replayed tool/final output, and preserve original JSON/unknown fields/IDs/flags/errors. Raw tool argument comparison prevents SDK coercion of boolean revisions or float durations and rejects extra fields. SDK-normalized usage remains separate; original missing/partial/invalid/zero values and independent totals are retained. Cost is unknown. A synthetic malformed counter produces the SDK's serializer warning without changing raw evidence.

ModelSettings/client retries are zero, parallel tool calls are disabled, ToolExecutionConfig concurrency is one, max output is 2048 tokens, max turns twelve, prepared HTTP eight and tool invocations 24. Per-run tracing and sensitive trace inclusion are disabled through RunConfig. HTTP phases/connect are 30/five seconds with a maximum 120-second overall deadline. Request size is checked before dispatch; response evidence is capped after buffering at 1 MiB, which is not a compressed-wire/memory bound. Prepared HTTP attempts and SDK lifecycle events differ when a budget fails before dispatch; neither is a fresh quality trial.

Actual SDK function_tool offloads synchronous functions through asyncio.to_thread. A blocked booking worker was released after cancellation and still committed a meeting. Application tools are now true async functions, with short synchronous SQLite operations on their owning event loop and no detached write thread. Run-active/cancelling/monotonic-deadline checks run before a write and inside the transaction before commit. SQLite busy waits are 100 ms; an expired transaction rolls back before release. A closed context fences queued late work. The library Runner/HTTP lifecycle remains native. Cancellation cannot roll back a tool commit that already completed; receipts retain that state.

Booking permission requires exact caller day/participant IDs/duration plus an offer observed in this run. Cancellation permission names one fixed target, separate from booking; one run cannot enable both. Reusing a request ID with a changed payload/operation fails. Exact existing requests are recovery reads, including a cancelled original booking. Cancellation preserves meetings/old confirmations and frees only the event's busy rows. Confirmation/notification tools require their caller-owned request. Another already-cancelled request is existing state, not a new cancellation or notice grant.

Fixtures are bounded to 4 MiB/1000 people/10000 independent blocks/1000 prior meetings. Strict schemas check fictional .example addresses, IANA zones, work windows, typed durations, identities and coherent imported active meetings. Participant lists are unique, 1–12; starts are half-hour UTC with no fractional seconds. UTC start days may contain another local date and end on another UTC day; weekday/work-hour checks use each participant's local interval, including exact closing midnight at work_end=24. Overnight shifts/holiday calendars are not implemented. Host IANA data supplies offsets; cross-platform timezone changes require requalification.

New SQLite DBs are reserved at 0600/new directories 0700; WAL/SHM inherit privacy. Initialization is exclusive; version-2 schema upgrades retain original rows and identity without guessed dataset/model history. Business snapshots use one SQLite read transaction and include busy/event/request/cancellation/outbox state. Transaction revisions track availability, not notification count. Concurrent identical bookings recover once; competing requests are fenced by revision. Competing cancellations commit once and report existing state for the other caller. No outside editor participates in application ownership/invariants.

Private schema-1 receipts persist task/instruction/state hashes, explicit scope, exact fixture identity, original HTTP and normalized SDK/tool evidence separately. A recording fault stops subsequent work; a post-commit fault never implies rollback. Final state/effects are re-read from SQLite even on failure. If final recording fails, the last file can remain running and the exception has in-memory evidence_error. No automatic mutation retry follows an uncertain publication. Draft final prose requires human/semantic review; actual_effects/state are authoritative.

Ten hash-bound cases/four profiles include coherent busy human history, ambiguous identities, no overlap, changed availability, DST transitions, UTC/local date boundaries and cancellation recovery. The manifest selects task facts only; CLI write flags remain caller-owned. Focus metadata is excluded from model prompts. Prior human_import rows have no provider usage or model execution claims. Fresh locked wheel/sdist installs exercise installed console/module CLI, all private cases, key preflight, actual calendar mutations and recovery outside checkout. macOS/Linux signals are tested; Windows signal behavior is unqualified.

Live OpenAI judgments, provider retention/billing, new Firedrill persisted cases and publication/licensing remain external gates.
